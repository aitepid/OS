TRADE SECRET POLICY -- Trade Secret Protection and Licensing Strategy
======================================================================

This document defines the scope and management strategy for trade
secret protection of the HicOS project.

NOTE: The current repository is a public GitHub repository.
Content that has been publicly disclosed is NOT eligible for trade
secret protection. This document primarily provides a strategy
framework for potential future commercialization.


======================================================================
PART 1: CURRENT IP PROTECTION STRATEGY ANALYSIS
======================================================================

HicOS is currently published on a public GitHub repository.
This means:

AVAILABLE PROTECTION MECHANISMS

  (1) Copyright Protection -- Fully applicable
      Code remains copyright-protected even when publicly
      available. Others may view the code but may not copy,
      modify, or distribute without permission.

  (2) Patent Protection -- Applicable (time-limited)
      Patents may still be filed within 12 months of public
      disclosure (US: 12-month grace period).
      First disclosure: 2026-03-19
      Patent application deadline: 2027-03-19
      STRONGLY RECOMMENDED to complete patent applications
      before this date!

  (3) Open Source License -- Currently not set
      The current repository has no LICENSE file, defaulting
      to "All rights reserved."
      This means others cannot legally use the code.
      Recommendation: Explicitly choose a license strategy
      (see below).

NOT APPLICABLE PROTECTION MECHANISMS

  (4) Trade Secrets -- Not applicable after public disclosure
      Source code published in a public repository cannot be
      claimed as trade secrets.
      However, the following can still be trade secrets if
      never publicly disclosed:
      - Unpublished internal design documents
      - Unpublished performance optimization strategies
      - Unpublished customer information / business plans


======================================================================
PART 2: LICENSE STRATEGY RECOMMENDATIONS
======================================================================

Option A: Maintain All Rights Reserved (current status)
  Use case: Purely personal project, no intention for others to use
  Pros: Maximum rights retention
  Cons: Limits community participation and dissemination

Option B: Permissive Open Source (MIT / Apache 2.0)
  Use case: Desire broad dissemination, building Hilbert-Lang
            ecosystem
  Pros: Community-friendly, easy adoption
  Cons: Others may freely use, even for commercial purposes
  Note: Apache 2.0 includes a patent grant clause, providing
        some protection

Option C: Copyleft (GPL v3)
  Use case: Require derivative works to also be open source
  Pros: Prevents others from using code in closed-source products
  Cons: Some limitations on commercial partnerships

Option D: Dual License
  Use case: Want both open source presence and commercial
            monetization
  Approach: Community edition under GPL, commercial edition
            separately licensed
  Pros: Balances open source dissemination and commercial revenue
  Example: Variation of the Linux (GPL) + commercial support model

Option E: Source-Available but Not Open Source
           (BSL / SSPL / Custom)
  Use case: Code publicly auditable, but commercial use restricted
  Approach: Allow viewing and non-commercial use; commercial use
            requires licensing
  Examples: Elastic License 2.0, Business Source License


======================================================================
PART 3: PATENT APPLICATION TIME WINDOW (CRITICAL!)
======================================================================

China Patent Law (2021 Amendment):
  Article 24: An invention-creation for which a patent is applied
  shall not lose its novelty if, within six months before the filing
  date, one of the following events has occurred:
  (1) First disclosed for public interest during a national emergency
      or extraordinary circumstance;
  (2) First exhibited at an international exhibition sponsored or
      recognized by the Chinese government;
  (3) First published at a prescribed academic or technical
      conference;
  (4) Content disclosed by others without the applicant's consent.

  NOTE: Public disclosure on GitHub does NOT fall under the above
  grace period provisions!
  Recommendation: Consult a patent attorney regarding specific
  applicability.

United States Patent Law (35 U.S.C. Section 102(b)):
  Applications may be filed within 12 months of first public
  disclosure (grace period).
  First disclosure: 2026-03-19
  US patent application deadline: 2027-03-19

URGENT RECOMMENDATION

  If patent applications are intended, take action promptly:
  (1) Contact a patent attorney/agency
  (2) File at least one PCT international patent application within
      the grace period (PCT can simultaneously cover China, US,
      Europe, and other countries)
  (3) File a Chinese priority application first, then extend to
      other countries within 12 months


======================================================================
PART 4: IP STRATEGY FOR FUTURE COMMERCIALIZATION PATHS
======================================================================

4.1 Academic / Educational Path
  - Publish academic papers (describing Hilbert curve OS
    architecture)
  - File patents BEFORE paper publication (publication also
    destroys novelty)
  - Use MIT/Apache license to encourage academic citations

4.2 Commercial Path
  - File core patents (Schemes 1, 2, 3)
  - Adopt dual-license model
  - Retain commercial licensing rights for core modules
  - Open non-core modules to promote ecosystem development

4.3 Open Source Community Path
  - Choose GPL v3 or Apache 2.0
  - Earn revenue through services/support/customization
  - Retain "HicOS" / "Hilbert-Lang" trademarks
