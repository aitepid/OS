C. NON-PATENT LITERATURE (NPL)
----------------------------------------------------------------------

  C1. David Hilbert, "Ueber die stetige Abbildung einer Linie
      auf ein Flaechenstueck," Mathematische Annalen, vol. 38,
      pp. 459-460, 1891.
      Relevance: Original description of Hilbert space-filling
      curves. Foundation of the mathematical concept used in
      the invention.

  C2. Google Inc., "S2 Geometry Library," 2017,
      https://s2geometry.io/
      Relevance: Application of Hilbert curves for geographic
      spatial indexing. Demonstrates Hilbert curve use in
      software but NOT in OS kernel architecture.

  C3. B. Moon, H.V. Jagadish, C. Faloutsos, and J.H. Saltz,
      "Analysis of the Clustering Properties of the Hilbert
      Space-Filling Curve," IEEE Transactions on Knowledge and
      Data Engineering, vol. 13, no. 1, pp. 124-141, 2001.
      Relevance: Analysis of Hilbert curve locality properties
      in database indexing context.

  C4. Linux Kernel source code, version 6.x, kernel.org, 2024.
      Files: mm/page_alloc.c, kernel/sched/, ipc/
      Relevance: Conventional OS kernel architecture using linear
      address space organization (prior art for comparison).

  C5. Niklaus Wirth, "Project Oberon: The Design of an Operating
      System, a Compiler, and a Computer," revised edition,
      Addison-Wesley, 2013.
      Relevance: Single-language OS design. Does not use Hilbert
      curve addressing. Prior art for comparison.

  C6. Terry A. Davis, "TempleOS," 2003-2017,
      https://templeos.org/
      Relevance: Self-contained OS with custom language (HolyC).
      Does not use Hilbert curve addressing.

  C7. H. Sagan, "Space-Filling Curves," Springer-Verlag, 1994.
      ISBN: 978-0-387-94265-0.
      Relevance: Comprehensive treatment of space-filling curves
      including Hilbert curves. Mathematical foundation.

  C8. A.R. Butz, "Alternative Algorithm for Hilbert's Space-
      Filling Curve," IEEE Transactions on Computers, vol. C-20,
      no. 4, pp. 424-426, 1971.
      Relevance: Efficient computation algorithm for Hilbert
      curve encoding/decoding.

C. NON-PATENT LITERATURE (NPL)
----------------------------------------------------------------------

  C1. Ken Thompson, "Reflections on Trusting Trust,"
      Communications of the ACM, vol. 27, no. 8, pp. 761-763,
      August 1984.
      Relevance: Describes the security implications of compiler
      self-bootstrapping and trust chains. Foundational motivation
      for single-language toolchains.

  C2. GCC Project, "GCC Internals Manual," Free Software
      Foundation, https://gcc.gnu.org/onlinedocs/gccint/
      Relevance: Self-bootstrapping C compiler. Requires separate
      assembler (gas) and linker (ld). Prior art for comparison.

  C3. LLVM Project, "LLVM Language Reference Manual,"
      https://llvm.org/docs/LangRef.html
      Relevance: Multi-stage compilation infrastructure (C++
      implementation). Used by Rust and other languages.
      Prior art for comparison.

  C4. The Rust Project, "rustc dev guide,"
      https://rustc-dev-guide.rust-lang.org/
      Relevance: Self-hosting compiler written in Rust, but
      depends on LLVM (C++) backend. Prior art for comparison.

  C5. Niklaus Wirth, "Project Oberon: The Design of an Operating
      System, a Compiler, and a Computer," revised edition,
      Addison-Wesley, 2013.
      Relevance: Closest prior art for single-language OS.
      Oberon compiler + OS in Oberon language. However: requires
      external compiler for initial bootstrap, does not produce
      bare-metal bootable disk images from toolchain alone.

  C6. Terry A. Davis, "TempleOS," 2003-2017,
      https://templeos.org/
      Relevance: OS with self-hosted compiler (HolyC). However:
      initial compiler implementation mixes HolyC with x86
      assembly. Not purely single-language.

  C7. Jeremy Soller et al., "Redox OS," https://www.redox-os.org/
      Relevance: OS written primarily in Rust. Depends on LLVM
      (C++) backend. Not single-language.

  C8. Andrew S. Tanenbaum, "MINIX 3,"
      https://www.minix3.org/
      Relevance: Educational OS in C + assembly. Multi-language.
      Prior art for comparison.

  C9. Intel Corporation, "Intel 64 and IA-32 Architectures
      Software Developer's Manual," 2024.
      Volumes 1, 2A, 2B, 2C, 3A, 3B, 3C, 3D.
      Relevance: Authoritative reference for x86_64 instruction
      encoding, CPU mode transitions, and system programming.

  C10. System V Application Binary Interface, AMD64 Architecture
       Processor Supplement, version 1.0, 2024.
       Relevance: Calling convention used by the toolchain's
       code generator.

  C11. QBE Compiler Backend, https://c9x.me/compile/
       Relevance: Lightweight compilation backend (approximately
       8,000 lines of C). Similar goals of simplicity, but
       implemented in C and does not include OS integration.
