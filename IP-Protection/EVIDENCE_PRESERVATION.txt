PART 2: RECOMMENDED SUPPLEMENTARY EVIDENCE PRESERVATION MEASURES
======================================================================

2.1 Git Signed Tags -- Strongly Recommended

  Procedure:
    (1) Generate GPG key pair:
        gpg --full-generate-key
    (2) Configure Git:
        git config user.signingkey <KEY_ID>
    (3) Create signed tag:
        git tag -s v6.0-ip-baseline \
          -m "IP protection baseline: 186 .hl files, 48657 lines"
        git push origin v6.0-ip-baseline

  Effect: GPG signature provides cryptographic-level time + identity
  proof.

2.2 Trusted Timestamp Services -- Recommended

  (a) China Trusted Timestamp Service (tsa.tsa.cn)
      - Submit .tar.gz archive of repository for trusted timestamp
        signing
      - Resulting timestamp certificate is admissible as legal
        evidence

  (b) International Trusted Timestamps
      - FreeTSA (freetsa.org): Free RFC 3161 timestamps
      - Procedure:
        openssl ts -query -data hicos-archive.tar.gz -sha256 \
          -out request.tsq

  (c) Blockchain Notarization (optional)
      - Record SHA-256 hash of repository archive on blockchain
      - Services: Ant Chain / Zhixin Chain / Originstamp

2.3 China Copyright Protection Center Registration
    -- Strongly Recommended

  Registration type: Computer Software Copyright Registration
  See COPYRIGHT_NOTICE.txt Part 3 for specific materials
  Expected timeline: 30-60 business days
  Fee: 250 RMB per work (2024 standard; verify at official website)

2.4 Notarized Preservation (Major Dispute Prevention) -- Optional

  If IP disputes are anticipated, visit a notary office to:
  - Notarize the complete current state of repository source code
  - Notarize GitHub page screenshots
  - Notarize QEMU boot demonstration
  Fee: Several hundred to several thousand RMB

PART 3: DAILY EVIDENCE MAINTENANCE PRACTICES
======================================================================

3.1 Commit Practices
  - Commit each meaningful change promptly (do not accumulate
    changes for a single large commit)
  - Commit messages should include functional descriptions
    (already in practice: "Iteration XXX: ...")
  - This is an area where the current project already excels

3.2 Periodic Archiving
  - Create a Git signed tag after each major iteration
  - Recommended frequency: one signed tag every 5-10 iterations

3.3 Build Artifact Preservation
  - Save key version build artifacts:
    hicos-hl.img / hicos-uefi.img / kernel.bin
  - Record SHA-256 checksums
